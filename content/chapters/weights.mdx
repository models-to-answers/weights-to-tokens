## Architecture, weights, and tokens

The architecture describes the operations and connections in the model. The
weights are the learned numeric settings used by those operations. A tokenizer
is the translation layer between human text and the token IDs the model reads
and predicts.

A checkpoint stores weight tensors and enough metadata to reconstruct them. It
is an artifact, not a running service: serving software still has to load it,
allocate memory, and execute compatible operations.

During inference, the trained weights remain fixed. The runtime reads them
repeatedly while producing each next-token prediction.

### What the model actually does

An autoregressive model repeatedly computes a distribution over its vocabulary,
selects a token, appends it, and runs again. Capability comes from learning
enough structure to make that apparently simple prediction well.

### Where the billions come from

Depth grows parameter count roughly linearly. Width appears inside square
projection matrices and grows it much faster. Vocabulary embeddings matter
most for smaller models, while feed-forward blocks dominate many dense large
models.
