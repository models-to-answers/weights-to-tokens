## More capacity has more than one meaning

Independent replicas each hold a complete model and serve different requests.
They increase aggregate throughput but do not help an oversized model fit on
one device.

Model-parallel approaches make several GPUs cooperate on one request. Tensor
parallelism divides operations within layers; pipeline parallelism divides
layers; expert parallelism routes tokens among expert partitions.

Cooperation introduces communication and synchronization. The useful question
is not simply “How many GPUs?” but whether they are replicating work or sharing
one model execution.

### Parallelism is a placement decision with a communication bill

Tensor parallelism shards matrix operations and typically requires collectives
inside every layer. Pipeline parallelism places layer ranges on different
devices and trades communication for pipeline bubbles and scheduling
complexity. Expert parallelism routes tokens to selected experts and can create
load imbalance. Data-parallel replicas communicate little while serving
independent requests, but each replica must fit a complete serving copy.

Topology matters: communication within a high-bandwidth GPU fabric differs
from crossing host or rack boundaries. Collective latency becomes part of
every cooperative token step, so adding devices can reduce usable capacity or
latency if the model already fits efficiently on one GPU.

KV-cache ownership must follow the ranks that consume it. Moving a request to
another worker can lose locality or require expensive cache transfer.
