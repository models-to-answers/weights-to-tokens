## Move fewer bytes, and move them together

Registers are private to threads. Shared memory is programmer-managed storage
shared by a block. Caches sit between SMs and device memory, while HBM provides
large capacity and high aggregate bandwidth at longer latency.

When neighboring threads request neighboring aligned addresses, the memory
system can combine their requests into fewer transactions. Scattered access
usually transfers more data and spends more transactions to serve the same
useful values.

Performance depends on both access pattern and reuse. Arithmetic intensity
helps explain whether a kernel is limited primarily by compute or data movement.

### Transactions, tiling, and bank conflicts

A warp’s addresses are grouped into aligned memory sectors or transactions.
Contiguous aligned accesses use transferred bytes efficiently; strided or
scattered accesses may request the same number of values through many more
transactions. Shared-memory tiling pays for a coalesced global load once and
reuses the values across threads. The tile design must also avoid shared-memory
bank conflicts and excessive synchronization.

</ExpertOnly>

## Choose an optimization from the bottleneck

The roofline model compares the work performed with bytes moved. A kernel below
the sloped bandwidth roof needs better locality, reuse, coalescing, or fusion.
A kernel near the flat compute roof needs more effective math pipelines,
instruction efficiency, or algorithmic change.

Arithmetic intensity is operations per byte moved from the measured memory
level. Below the sloped roof, reduce traffic or increase reuse through layout,
coalescing, tiling, caching, or fusion. Near the flat roof, inspect instruction
mix, tensor-core eligibility, dependencies, and achieved issue rate. A roofline
classifies the likely bound; a profiler identifies the specific cause.

</ExpertOnly>

## A practical reduction checklist

1. Profile first: identify the hottest kernel and its dominant stall reason.
2. Remove unnecessary host-device transfers and intermediate tensors.
3. Make neighboring lanes access neighboring aligned addresses.
4. Reuse values in registers, shared memory, or cache.
5. Fuse operations when it avoids materializing large intermediates.
6. Check occupancy resources without treating occupancy as the final goal.
7. Re-measure correctness and end-to-end latency after every change.

## CPU-to-GPU translation table

| CPU-oriented term | Closest GPU mental model | Important difference |
| --- | --- | --- |
| CPU socket | GPU device | The GPU is a throughput coprocessor with its own memory |
| CPU core | Streaming multiprocessor | An SM hosts many warps and several execution pipelines |
| Software thread | CUDA thread | Threads issue in 32-thread warps |
| SIMD vector | Warp lanes | Branch masks can make only some lanes active |
| L1/L2 cache | Shared/L1 and L2 | Shared memory is explicitly managed by a block |
| System RAM | HBM | HBM has high bandwidth but is separate from host memory |
