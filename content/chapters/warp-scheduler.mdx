## Ready work hides waiting

A warp contains 32 CUDA threads. At an instruction-issue opportunity, a warp
scheduler chooses an eligible warp whose operands and execution resources are
ready.

If a warp is stalled on memory or a dependency, another resident warp can
issue. This rapid interleaving is how GPU concurrency hides latency without
making the original memory operation itself faster.

High theoretical occupancy only creates the opportunity to hide latency.
Dependencies, divergence, and instruction mix determine achieved utilization.

## One instruction stream, different lane decisions

CUDA threads hold individual state, but the threads in a warp issue together.
When a branch divides the warp, hardware masks the lanes for one path, then the
other, before reconverging. Divergence is expensive when both paths contain
substantial work.

### Eligibility, issue, and the resource triangle

The scoreboard tracks whether operands are ready. A scheduler selects among
eligible resident warps and issues an instruction to a compatible available
pipeline. A memory instruction calculates addresses and enters the load/store
path; its warp remains unavailable until dependencies resolve while other
warps may issue.

Registers per thread, shared memory per block, and threads per block jointly
limit residency. Higher occupancy can provide more candidates for latency
hiding, but it can also force smaller tiles or more spills. The goal is
measured throughput, not maximum occupancy as an isolated number.

Preemption and fairness policies vary by architecture and runtime. The durable
model is that scheduling interleaves eligible warp instructions; it does not
make a stalled instruction complete faster.
